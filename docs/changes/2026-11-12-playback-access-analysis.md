# 播放速度与安全作用域访问：静态分析

本记录只依据当前源码分析。Windows 环境未运行 Swift 编译、Thread Sanitizer、真实安全作用域授权或 macOS 图形测试；现有工作区改动均保留。

## 播放速度

`OverlayWindowController` 在设置变化时写入 `AnimationPlayer.speed`；`CVDisplayLink` 后台回调在 `stateLock.withLock` 内读取同一属性。写入方不持有 `stateLock`，所以读取方单独持锁不能建立互斥，源码存在未同步的跨线程读写。当前没有 Thread Sanitizer 的运行证据，不能据此量化出现频率或后果。

建议后续将速度与播放状态放进同一受锁保护的数据，外部读写也通过同一把锁；回调持锁时直接读取锁内状态，避免在锁内调用再次获取同一锁的属性。应保留 0.1–8.0 的限制和现有 CVDisplayLink、帧索引去重行为。需测试速度边界、播放中快速切换、暂停恢复，并在 Mac 上用 Thread Sanitizer 验证；检查该方案的实时性能。

## 安全作用域

`loadAssetFromBookmark` 每次解析后尝试开始访问。加载失败时，如果本次开始成功，会停止本次访问；成功后将本次是否开始成功写入 `currentAssetIsSecurityScoped`。旧访问只在旧 URL 与新 URL 不同时停止。

对于旧访问已开始且新旧 URL 相同的成功加载，源码存在两种待验证路径：

1. 本次也开始成功：旧访问没有停止，状态只记录一个活动访问；之后析构最多停止一次。
2. 本次未开始：旧访问没有停止，但状态被写成 false；之后析构不会停止旧访问。

同路径的普通 `loadAsset(url:)` 成功替换也会把新状态设为 false，同时跳过旧访问的停止。不同路径替换和新加载失败的路径需要一并回归；视频需要在播放结束或替换之前保持其所需访问。以上是基于调用次数和状态赋值的静态推断，真实 API 返回及资源行为仍需 Mac 验证。

建议后续按每次成功开始的访问独立记账：新资源成功接管后释放旧访问，即使 URL 相同；失败只释放新取得的访问并保持旧资源状态。应通过可注入访问接口统计 start/stop 次数，覆盖同 URL 成功/失败、不同 URL、直接导入、失败回滚及析构，再用真实沙盒授权素材复验。避免在未验证视频生命周期前提前停止新访问。
