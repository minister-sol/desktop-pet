# 第一阶段离线补充审查

审查范围：提醒加载、编辑、展示与 CI 配置。仅依据当前源码静态检查；Windows 环境没有 Swift、Xcode 或 macOS 图形会话，未运行构建、测试或交互。保留现有未提交改动。

## 待处理问题

1. **加载失败后的错误状态不够明确。** `ReminderScheduler` 初始化加载失败时保持 `ready = false`；`persist` 在此状态直接返回。`ReminderView.save` 的输入校验会覆盖原始读取错误，而后续有效输入不会恢复原始错误；当前代码中错误仍非空，尚未发现用户操作能将其清空，因此不能断言会误报成功。需要验证损坏文件后的错误提示和恢复路径，并考虑用显式保存结果代替对共享错误状态的判断；须确保原始文件不被覆盖。
2. **待查看列表可能超出窗口可用区域。** `ReminderView` 将 pending 的 `ForEach` 直接放在固定高度 `VStack` 内，只有提醒定义列表自身有滚动容器。多条或长文本时需检查是否被裁剪、关闭按钮能否访问；考虑将待查看区域纳入滚动容器，并在实机测试不同数量与窗口尺寸。
3. **提醒关闭失败缺少桌面附近的错误反馈。** 桌面按钮只调用 `dismiss`；若保存失败，提示仍留在原位，错误只在提醒设置面板显示。需验证用户能否理解并恢复，避免把未保存的关闭操作当作成功。
4. **展示队列属于单个宠物窗口。** 同刻到期后隐藏或移除承载提示的宠物，待查看数据仍在，但不会自动转移到其他可见宠物；确认这是否满足预期，并在有多个宠物和隐藏/移除场景下验收。现有约定至少保留菜单栏入口。
