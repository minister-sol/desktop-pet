# 第一阶段：先实现、后验收的执行顺序

**目标：** Actions 排队且没有 Mac 时继续完成点击互动和本地每日提醒的源码；macOS 构建与运行验收安排在环境可用之后。

**依据：** [第一阶段实施计划](2026-11-11-desktop-companion.md)。原计划的功能范围和行为约定不变，本文件仅调整顺序。现有未提交工作必须保留并先审查。

## 约束与状态

- 保持 AppKit + SwiftUI、Apple 框架、透明窗口、Spaces、菜单栏模式及现有播放和存储兼容。
- 当前工作区已有未验证的点击交互、XCTest target 和 CI 配置；不能称为已通过，也不能覆盖已有 `AGENTS.md` 修改。
- 用户明确要求把测试放到后面；实现期间仍做不依赖 macOS 的静态检查。未经编译的 Swift 代码视为待验证源码。
- 不推送、不合并、不发布，除非用户另行要求。

## 顺序

1. **审查并完成点击互动。** 检查 `PetView.swift` 和 `OverlayWindowController.swift` 的现有改动：4 点阈值、拖动后不触发点击、锁定位置可点击、穿透不接收事件、问候自动消失。检查视频层是否遮挡提示，并修正发现的问题。
2. **提醒数据。** 在 `DesktopPet/Reminders/Reminder.swift` 和 `ReminderStore.swift` 定义 UUID、文本、小时、分钟、启用状态；验证非空、最多 200 字符和合法时间。使用 Application Support 下独立 plist 和原子写入；损坏或写入失败时保留原文件并向调用方报告错误，不改动原有宠物数据。
3. **提醒调度。** 在 `ReminderScheduler.swift` 计算当前时区下下一次每日触发，启停和删除时重新安排；监听唤醒、时钟和时区变化，跳过错过的提醒。持久化每日已展示状态，处理同一时刻多条提醒及跨日清理，提供注入时间和日历的接口。
4. **展示与设置。** 在 `ReminderView.swift` 提供新增、编辑、删除、启停和保存错误提示；接入菜单栏。到期提醒在可见宠物附近非模态显示，并在无宠物或隐藏时保留菜单栏待查看入口；逐条关闭，不抢焦点。
5. **整合与静态检查。** 登记新增文件到 Xcode 工程、现有手工 `swiftc` 构建清单和 CI；更新使用说明，说明运行、睡眠、时区和不补发限制。检查差异、工程引用和配置格式，记录不能在当前环境验证的问题。
6. **环境恢复后统一验证。** 在 macOS 执行 Debug 构建、确认 XCTest 数量大于零并运行回归测试；覆盖提醒验证、持久化、日界线、夏令时、时区、唤醒和去重。人工检查点击、拖动、穿透、透明 GIF、全屏 Space、隐藏宠物及重启。记录 runner 架构、系统、Xcode、命令和结果，修复后重新验证。

## 交付状态

第 1–5 步完成后只能称为“未构建的源码候选版本”；只有 macOS 构建与测试实际通过后才能称为“CI 构建通过的候选版本”。图形交互未经人工验收时须单独标明。
